story has verifiable acceptance criteria in Given/When/Then form, its dependencies
(prerequisite stories by id) and the automated tests that prove it. Generated by
`tools/build_backlog.py` from a single data table; a spreadsheet version is in
`docs/Monster_Tamers_Backlog_completed.xlsx`.

How to re-run the evidence: see *Tests* in the README (unit tests, Newman component,
integration and acceptance collections, concurrency test).

## Acceptance criteria

### US-01 - Create an account

*Mandatory (red)* - **Done**

- Given a username of 3-20 letters, digits or underscores that is not taken and a password of at least 8 characters, When I POST /auth/register, Then I get 201, a player id and a JWT, and my profile and starter collection exist.
- Given a username that is already taken, When I register, Then I get 409.
- Given an invalid username, a too-short password or an empty body, When I register, Then I get 400 and nothing is created.
- Given any successful registration, Then the password is never returned and is stored only as a scrypt hash that is also encrypted in the database.

- **Dependencies:** none
- **Implemented by:** auth: POST /auth/register; players: POST /internal/players
- **Verified by:** Postman auth 'register - *'; acceptance 'US-01'; test_field_crypto

### US-02 - Log in

*Mandatory (red)* - **Done**

- Given valid credentials, When I POST /auth/login, Then I get 200 and a bearer JWT with an expiry.
- Given a wrong password, an unknown user or an injection string, When I log in, Then I get 401 with the same message in every case (no user enumeration).

- **Dependencies:** US-01
- **Implemented by:** auth: POST /auth/login, GET /auth/me
- **Verified by:** Postman auth 'login - *', 'me - *'; acceptance 'US-02'

### US-03 - Have my progress available when I return

*Mandatory (red)* - **Done**

- Given I played encounters and logged out, When I log in again, Then my level, XP and collection are exactly as before.
- Given the whole backend is restarted, When I log in again, Then the same progress and history are returned (PostgreSQL volume).

- **Dependencies:** US-01, US-02, US-06
- **Implemented by:** players: GET /players/me; db volume `db_data`
- **Verified by:** acceptance 'US-03'; pytest test_progress_survives_a_new_login; manual restart check (README)

### US-05 - Have my account data protected

*Mandatory (yellow)* - **Done**

- Given no, a malformed or an expired token, When I call any protected endpoint, Then I get 401.
- Given another player's team, encounter or history entry, When I request it, Then I get 404 (read) or 403 (use).
- Given a request to an /internal/* endpoint or to the db-manager without the internal key, Then I get 403.
- Given a database dump, Then no password hash can be read without the data-encryption key held only by the db-manager.
- Given any hop between client, gateway and services, Then it uses HTTPS (TLS 1.3 only).
- Given a path such as /players/../internal/..., Then the gateway answers 404 and the internal endpoints stay unreachable.
- Given repeated wrong logins for one account, Then the gateway answers 429 with Retry-After, and an unknown account takes as long to refuse as an existing one.

- **Dependencies:** US-01, US-02
- **Implemented by:** gateway + every service: JWT check; db-manager: AES-256-GCM columns; init job: TLS and secrets
- **Verified by:** Postman '* - missing token' and 'another player' requests, internal '403' requests; acceptance 'US-05'; pytest test_a_player_cannot_use_or_read...; test_field_crypto; test_secrets; test_init_provisioning

### US-06 - Receive an initial set of monsters

*Mandatory (red)* - **Done**

- Given a new account, When I read my collection, Then I own exactly 3 starter monsters (the 3 lowest catalogue ids).

- **Dependencies:** US-01
- **Implemented by:** players: POST /internal/players (called by auth)
- **Verified by:** Postman players 'collection - valid token'; acceptance 'US-06'

### US-09 - View the monsters I own

*Mandatory (red)* - **Done**

- Given I own monsters, When I GET /players/me/monsters, Then each entry has player_monster_id, name, element, hp, attack, defence, rarity, level and image_url.
- Given I am not logged in, Then I get 401. Given another player, Then they never see my monsters.

- **Dependencies:** US-06
- **Implemented by:** players: GET /players/me/monsters
- **Verified by:** Postman players 'collection - *'

### US-10 - Browse all monsters available in the game

*Mandatory (red)* - **Done**

- Given the seeded catalogue, When I GET /monsters without a token, Then I get at least 10 monsters, each with an image URL and its characteristics.
- Given limit=3, Then at most 3 are returned; given limit=abc, Then I get 400.

- **Dependencies:** none
- **Implemented by:** monsters: GET /monsters
- **Verified by:** Postman monsters 'catalogue - *'

### US-11 - View a monster's image and characteristics

*Mandatory (red)* - **Done**

- Given an existing monster id, When I GET /monsters/{id}, Then I get its element, hp, attack, defence and rarity; and /monsters/{id}/image returns an image (SVG).
- Given an unknown id, Then I get 404.

- **Dependencies:** US-10
- **Implemented by:** monsters: GET /monsters/{id}, /monsters/{id}/image
- **Verified by:** Postman monsters 'details - *', 'image - *'

### US-12 - Have an earned monster added to my collection

*Mandatory (red)* - **Done**

- Given I win an encounter and still miss catalogue monsters, When the encounter is resolved, Then at most one monster I do not own may be added with source 'reward', and it appears in my collection and survives a restart.
- Given I lose, Then no monster is added. Given I own every monster, Then no duplicate is created.
- Given the reward and the encounter result, Then they are stored in the same transaction.

- **Dependencies:** US-06, US-19
- **Implemented by:** encounters: reward selection; db-manager: batch transaction, UNIQUE(player_id, monster_id)
- **Verified by:** acceptance 'US-12'; pytest test_win_is_persisted_atomically...; test_reward_conflict_is_retried_and_succeeds; test_progress_integrity

### US-14 - Create a team using monsters from my collection

*Mandatory (red)* - **Done**

- Given 1-3 distinct monsters that I own, When I POST /teams, Then I get 201 and the team is stored and listed.
- Given a monster I do not own (also another player's), a duplicate, more than 3 monsters or none, Then I get 422 with the violations.
- Given a body that is not a list of integers, Then I get 400.

- **Dependencies:** US-09
- **Implemented by:** teams: POST /teams, GET /teams, GET /teams/{id}
- **Verified by:** Postman teams 'create team - *', 'list teams - *', 'get team - *'; pytest team rules

### US-15 - Replace or remove monsters in my team

*Mandatory (red)* - **Done**

- Given one of my teams, When I PUT /teams/{id} with new members, Then only the new members remain.
- Given one of my teams, When I DELETE it, Then it is gone and a second delete gives 404.
- Given another player's team, Then update and delete give 404.

- **Dependencies:** US-14
- **Implemented by:** teams: PUT /teams/{id}, DELETE /teams/{id}
- **Verified by:** Postman teams 'replace members - *', 'delete team - *'

### US-16 - Know whether my team satisfies the game rules

*Mandatory (red)* - **Done**

- Given a stored team, When I POST /teams/{id}/validate, Then I get valid=true or the list of violations.
- Given the rules (1-3 monsters, all owned, no duplicates), Then create and update enforce exactly the same checks.

- **Dependencies:** US-14
- **Implemented by:** teams: POST /teams/{id}/validate; team_rules.validate_team
- **Verified by:** Postman teams 'validate team - *'; test_team_rules

### US-17 - View available encounters and their characteristics

*Mandatory (red)* - **Done**

- Given I am logged in, When I GET /encounters, Then I see every template with its name, difficulty 1-5 and wild monster.
- Given no token, Then I get 401.

- **Dependencies:** US-02
- **Implemented by:** encounters: GET /encounters
- **Verified by:** Postman encounters 'list encounters - *'

### US-18 - Start an encounter with my selected team

*Mandatory (red)* - **Done**

- Given a valid team of mine and an existing template, When I POST /encounters, Then I get 201 with the resolved encounter.
- Given another player's team, Then 403; an unknown team or template, Then 404; non-integer ids or an empty body, Then 400; no token, Then 401.
- Given a body that also contains 'outcome' or 'xp_gained', Then those fields are ignored.

- **Dependencies:** US-14, US-16, US-17
- **Implemented by:** encounters: POST /encounters
- **Verified by:** Postman encounters 'start encounter - *', 'client cannot choose the outcome'; test_encounters_service

### US-19 - Have an encounter resolved according to the game rules

*Mandatory (red)* - **Done**

- Given a valid team, When the encounter starts, Then the server alone computes the result with the rules in docs/game-rules.md and both win and loss are possible.
- Given a win, Then +20 XP; given a loss, Then +5 XP; and the level is derived from the XP.
- Given the teams or players service is down, Then 502 and nothing is persisted.

- **Dependencies:** US-18
- **Implemented by:** encounters: encounter_rules.resolve; docs/game-rules.md
- **Verified by:** test_encounter_rules; test_encounters_service; Postman encounters 'start encounter - valid team'

### US-20 - See the details of an encounter result

*Mandatory (red)* - **Done**

- Given an encounter of mine, When I GET /encounters/{id}, Then I get the outcome, my team snapshot, the wild monster, the resolution figures and the reward if any.
- Given another player's or an unknown id, Then I get 404.

- **Dependencies:** US-18
- **Implemented by:** encounters: GET /encounters/{id}
- **Verified by:** Postman encounters 'encounter details - *'; acceptance 'US-20'

### US-23 - View my previous encounters

*Mandatory (red)* - **Done**

- Given I played encounters, When I GET /history, Then I see only mine, newest first, with outcome and summary.
- Given limit=1, Then at most one entry; limit=abc, Then 400; no token, Then 401.

- **Dependencies:** US-18
- **Implemented by:** history: GET /history
- **Verified by:** Postman history 'history - *'

### US-24 - View the details of a previous encounter

*Mandatory (red)* - **Done**

- Given a past encounter of mine, When I GET /history/{id}, Then I get the full snapshot (team, wild monster, resolution, reward).
- Given I later delete the team, Then the snapshot is still returned. Given another player's id, Then 404.

- **Dependencies:** US-23
- **Implemented by:** history: GET /history/{id}
- **Verified by:** Postman history 'history detail - *'; acceptance 'US-23 US-24'

### US-25 - Have my collection, history and progress protected from tampering or loss

*Mandatory (yellow)* - **Done**

- Given a client request that contains an outcome, XP or reward, Then it is ignored: only the encounters service decides.
- Given an encounter, Then its result, any reward and the XP increase are written in ONE database transaction.
- Given 12 concurrent encounters of one player, Then the XP equals the sum of the individual gains, there are 12 history entries and no monster is granted twice.
- Given the XP, Then the level is computed by the database and cannot be written by any service.
- Given a restart of every container, Then all saved progress is still there.

- **Dependencies:** US-05, US-12, US-19
- **Implemented by:** encounters: atomic batch + `increment` op + retry; db: generated `level` column
- **Verified by:** pytest test_concurrent_encounters_keep_progress_consistent; test_encounters_service; acceptance 'US-25'; Postman 'client cannot choose the outcome'

### US-28 - Perform the main game actions through a simple interface

*Mandatory (red)* - **Done**

- Given the backend is running, When I open the static frontend (outside Docker), Then I can register, log in, browse the catalogue, see my collection, create a team, start an encounter and read my history.
- Given the frontend, Then it only calls the gateway over HTTPS and contains no game logic.

- **Dependencies:** US-02
- **Implemented by:** frontend/ (static HTML/JS, own container or http.server)
- **Verified by:** manual walkthrough in README; every call goes through the same endpoints covered by the integration collections

### US-04 - Choose or update my player name and avatar

*Optional (green)* - **Partial (avatar and faction; username fixed)**

- Given I am logged in, When I PATCH /players/me with an avatar of 1-40 characters or a faction up to 40 characters, Then the change is saved and returned.
- Given an empty or too long avatar, or an empty body, Then 400. The username itself is immutable by design (it is the login identifier).

- **Dependencies:** US-01
- **Implemented by:** players: PATCH /players/me
- **Verified by:** Postman players 'profile - *'

### US-08 - Choose a faction or equivalent starting affiliation

*Optional (green)* - **Partial (stored, no gameplay effect)**

- Given I am logged in, When I set a faction through PATCH /players/me, Then it is stored and shown in my profile (it does not yet change gameplay).

- **Dependencies:** US-04
- **Implemented by:** players: PATCH /players/me (faction field)
- **Verified by:** Postman players 'profile - update avatar and faction'
